LuaRocks for Node.js / npm Developers ​

NOTE

If you are coming from a Node.js background, transitioning to Lua and LuaRocks can feel unfamiliar. This guide acts as a Rosetta Stone to translate npm patterns into LuaRocks equivalents.

1. Quick Concept Mapping ​

Here is how key concepts translate between the Node.js and Lua ecosystems:

3. Core Differences Explained ​

A. Module Resolution: Node.js vs Lua ​

  • Node.js: When you write require("foo"), Node automatically crawls up your directory structure looking for a node_modules folder containing foo. It does this dynamically at runtime without any environment variable configuration.
  • Lua: When you write require("foo"), Lua checks two global string paths:
    1. package.path for pure-Lua modules (.lua files).
    2. package.cpath for binary C modules (.so or .dll files).

By default, Lua only searches standard system directories. To make Lua aware of rocks you've installed, you must modify these paths.

TIP

The Easy Way: Add this line at the very top of your entry file (e.g., main.lua or app.lua):

lua
require("luarocks.loader")

This automatically hooks into Lua's require and resolves files from your installed LuaRocks trees.

B. Project Isolation: Where is node_modules? ​

By default, npm install downloads dependencies to a local node_modules/ folder in your project root, while npm install -g installs them globally. By default, luarocks install does the opposite: it installs packages globally (system-wide) or user-wide (--local).

To achieve the node_modules project-isolation experience in LuaRocks, use local trees:

Step 1: Install to a local tree ​

Use the --tree flag (conventionally named lua_modules or env):

bash
luarocks install dkjson --tree lua_modules

This creates a lua_modules folder inside your project containing:

  • lua_modules/share/lua/5.x/ (pure Lua files)
  • lua_modules/lib/lua/5.x/ (compiled C binaries)
  • lua_modules/bin/ (scripts/executables)

Step 2: Running your project with local dependencies ​

To run your project and import modules from lua_modules/, you have two options:

Option 1: Require the loader in code (Recommended)

lua
-- app.lua
require("luarocks.loader")
local dkjson = require("dkjson")
-- Your logic here

Then run simply with:

bash
lua app.lua

Option 2: Shell environment integration Generate and apply the environment paths in your current terminal session:

bash
eval "$(luarocks path --bin --tree lua_modules)"
lua app.lua

4. The Manifest: package.json vs .rockspec ​

While Node.js uses JSON (package.json), LuaRocks uses Lua syntax for its manifest files, called rockspecs (e.g. project-1.0-1.rockspec).

Here is a side-by-side comparison of how key configuration sections compare:

Side-by-Side Example ​

npm (package.json) ​

json
{
  "name": "my-json-utils",
  "version": "1.0.0",
  "description": "JSON wrapper utilities",
  "main": "src/init.js",
  "dependencies": {
    "dkjson": "^2.5.0"
  },
  "devDependencies": {
    "busted": "^2.0.0"
  }
}

LuaRocks (my-json-utils-1.0-1.rockspec) ​

lua
package = "my-json-utils"
version = "1.0-1"
source = {
   url = "git://github.com/username/my-json-utils.git",
   tag = "v1.0"
}
description = {
   summary = "JSON wrapper utilities",
   license = "MIT"
}
dependencies = {
   "lua >= 5.1",
   "dkjson >= 2.5"
}
test_dependencies = {
   "busted >= 2.0"
}
build = {
   type = "builtin",
   modules = {
      ["my-json-utils"] = "src/init.lua"
   }
}

Key Differences in Rockspecs: ​

  1. Manifest File Name: The rockspec filename must match the pattern {package_name}-{version}.rockspec.
  2. Version Format: Versioning in LuaRocks uses two parts: the upstream version (e.g., 1.0) and the rockspec revision (e.g., 1), separated by a hyphen: 1.0-1.
  3. Build Block: Unlike npm, which assumes files are loaded via folders or bundlers, LuaRocks requires you to explicitly tell it how to build and map your modules in the build table. Using type = "builtin" is the easiest and most common way to map module names to file paths.

5. Quick Workflow Transitions ​

Starting a New Project ​

  • npm:
    bash
    mkdir my-app && cd my-app
npm init -y
  • LuaRocks:
    bash
    mkdir my-app && cd my-app
luarocks write_rockspec
    (This generates a template rockspec file based on the directory name).

Installing Dependencies for Development ​

  • npm:
    bash
    npm install dkjson
  • LuaRocks:
    bash
    luarocks install --tree lua_modules dkjson
    (To lock versions, add them to your rockspec file's dependencies list).

Running Tests ​

  • npm:
    bash
    npm test
  • LuaRocks:
    bash
    luarocks test
    (This relies on the test specification inside the rockspec file, commonly using busted as the runner).

Locking Dependencies ​

  • npm: Automatically creates package-lock.json when installing dependencies.
  • LuaRocks: Uses luarocks.lock. See Pinning versions with a lock file for details on setting up and updating lockfiles.
